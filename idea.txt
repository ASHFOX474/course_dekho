# CourseDekho — Complete Project Specification

## 1. The core idea

**CourseDekho** is a centralized course/resource management platform for **CSE students in Bangladesh**.

The problem is that university CSE resources are scattered across:

* Google Drive
* Facebook groups
* Messenger
* Different seniors' folders
* University-specific websites
* Random PDFs
* Question banks
* Slides
* Tutorials
* Books
* Practice problems

A student shouldn't have to search through dozens of places to find:

> "I am taking DSA. What topics do I need to study, in what order, and what resources/questions are available for each topic?"

CourseDekho solves this by organizing everything around:

```text
University
    ↓
Semester
    ↓
Course
    ↓
Topic / Roadmap
    ↓
Resources
```

For example:

```text
BUET
 ↓
Level 2 Term 1
 ↓
Data Structures & Algorithms
 ↓
1. Linked List
2. Stack & Queue
3. Tree
4. Graph
5. Greedy
6. Dynamic Programming
 ↓
Slides
Tutorials
Books
Questions
Practice Materials
LeetCode Problems
```

The previous discussion specifically moved away from a generic "career roadmap" and toward a **topic-level roadmap inside each course**, because that makes the database more meaningful and useful for the DBMS project.

```text
          ┌───────────┼───────────┐
```

* active/inactive status

Then the user has a role.

```text

Student / Teacher / Admin
```

There can be **multiple Admins**.

# 45. The final vision

The platform isn't simply:

> **"A website containing PDFs."**

It is:

> **A structured academic resource and course-management platform where courses are broken into ordered topics, resources are attached to those topics, students and teachers can consume and track content, teachers can contribute resources through an admin-controlled approval workflow, and administrators have complete control over the platform's users, academic structure, and content.**

The strongest part of the project from a **DBMS perspective** is the combination of:

```text
University
      ↓
Semester
      ↓
Course
      ↓
Topic / Roadmap
      ↓
Content
      ↓
User interaction
      ↓
Progress + Access + Bookmark
```

plus:

```text
Teacher
   ↓
Submission
   ↓
Admin Approval
   ↓
Published Content
```

That gives you substantially more than a simple CRUD database: you have **role-based access, many-to-many relationships, ordered entities, content specialization, moderation workflow, user activity, progress tracking, and bookmarking**.

**This is the specification I would now treat as the source of truth for the next ERD.**
